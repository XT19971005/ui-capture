# 图片拆分精修实施计划

> 执行采用 Superpowers 的测试先行与独立审查流程。

目标：完整拆分后提供“精修”，只修文字、简单面板和纯色矢量图标；图片保持原字节、位置、尺寸及样式。第一遍仍可继续拆分，精修不能替代未完成的拆分。

架构：继续使用现有 /jobs 与 RAM 会话，引入 mode=refine-ui。精修基于当前 scene 做原图视觉检查并输出允许的原生图层修改；禁止调用图像生成，禁止更改任何 image 节点、背景或会影响图片的父组。真实 PSD 导出及独立结构回读继续执行，有视觉问题保留 NEEDS_REVIEW 并允许下载。

技术：现有 Flask/Python、Codex 视觉规划、共享原生 PSD 工具、网页 JS。

## 约束

- 不重启正在运行任务的服务，不刷新用户页。
- 无自动磁盘工程缓存；临时文件成功/失败/取消清理，主动保存保留。
- 每次修改记入当天变更记录；同步技能、分享包及已有 Git 备份。
- 图片节点完整深拷贝保持，父组结构和作用于图片的样式不变。
- 内容准确；字体近似允许，不横向拉伸、不重叠，不凭空增加描边阴影。
- 部分修改无效则跳过并标出，不毁掉既有工程。失败/取消保留精修前工程，撤销可回到精修前。

## 任务

2. 前台：image-editor.js显示简洁“精修”按钮，完成/待校对可用、未完成禁用；smart-split.js传 refine-ui 与当前scene。复用进度/取消，完成记录本遍时间；失败回到精修前，不把完整工程变成未完成。源与edge同步。
3. 验证：受控模型响应但真实PSD导出/独立回读/下载，两个按钮并存不互相替代；实际浏览器点击、撤销、保存重开、取消、导出，无外部付费测试。没有真实模型复测时如实注明。
4. 收尾：当天变更记录、技能规则与分享文件更新；Git备份白名单更新。当前任务结束前不部署需重启的后台修改。
