## 目标与设计

现有 JavaScript 工作台 + 本机 Python 服务继续使用，无新账号或生成服务。

- 主画布“圈选编辑”：整张未拆图片也可直接进入；拆分工程处理一个已选图片层。在主画布自由手绘，Shift追加区域取并集，可撤销/重做。描述、参考图与候选放右侧，不另开替换弹窗。默认reference模式只交接选区裁图和描述作为新图参考，不改原图、不触发生成或保存；明确选择局部替换才生成回贴指定区域的候选。
- 独立“生成图片”支持文字或参考图，无需先上传拆分原图或选中层。用户主动生成后先预览独立素材，再手动下载PNG或添加新层；添加新层才改工程且不自动保存，不覆盖来源原图。主操作为“拆分 / 圈选编辑 / 生成图片”，低频动作放菜单。
- 选区在原始图层图片像素坐标定义，不以画布缩放像素作为生成坐标。图层位置、大小、旋转、蒙版、父组及未选层不变。局部结果仅合成回选择区域，区域外像素精确保持。
- 两模式生成均先产出候选，不改变工程。参考生图输出独立素材；只有局部替换模式的“应用替换”才替换来源层并隐藏旧版、一步撤销。取消/失败/切工程使候选失效。模型内容、边界自然度仍需看图，不将数据测试视为美术通过。
- “保存工程”才写工程库；本机网页默认保存工作区“工程文件”，由应用根目录父目录相对解析，便携移动仍有效。导入、移动、替换、精修、自动阶段/关闭 flush 不自动写。旧浏览器记录保留，不自动迁移；打开旧记录也不转存，明确保存才建立同ID磁盘版本。扩展兼容原存储，凭据保留。未保存改动离开页面需明确提示，刷新恢复最后手动版本。
- 图片工程的“回到初始”固定为首次完整拆分成功快照，并随手动保存/导入导出保留。打开、精修、手动保存不得重设。重新拆分成功产生新基准；未完成不设成完整拆分基准。旧工程缺少快照需说明，不能以当前修改状态冒充。

## 接口约定

保留 jobs mode `replace-image`；原矩形请求 `replacement: {targetId, region, prompt, reference}` 为兼容入口。自由选区及独立生成使用当前主任务实现的版本化请求，具体字段以生产校验和能力协商为准，不将旧矩形字段说明当作套索接口已完整定义。

- region 为 null（整层）或原图片像素整数框 `{x,y,width,height}`；reference 为 null 或 `{src,region}`，坐标同其自然图片尺寸。
- 后端 `image_replace.validate_replacement(scene, replacement)` 在模型前验证；`process` 沿用现有任务生命周期，增加 `replacement` 关键字参数。只返回候选 scene，不写工程库，不导出 PSD。
- 前端 `ShijieSmartSplit.replaceImage(doc, replacement, onProgress)` 复用任务连接/取消/清理。
- 替换与生成控制器通过工作台适配器访问当前工程，圈选操作在主画布，输入和预览在右侧；生成期间任务锁生效，应用前核对owner与完整输入快照。源图上传锁只允许未拆单原图的显式替换；普通锁定层/父组必须先解锁。
- 本地工程库使用 `/saved-projects` 元数据列表与单工程正文接口，手动保存去重图片后原子替换。令牌/同源、容量、版本冲突和损坏拒绝在服务端执行；磁盘确认成功后才更新已保存状态，失败不降级成浏览器静默写入。
- 基准元数据独立可版本化，避免递归包含自身；数据压缩、尺寸和恢复校验沿用工程编码器。初始快照不进入生成请求以免扩大模型输入。

## 审查重点

1. 套索并集及兼容矩形在图层局部像素而非舞台坐标；不同分辨率参考图不得串坐标，重叠选区不重复合成。
2. 保存基准不能递归膨胀；快照及候选不能通过异步回调污染新工程。
3. 点击取消后晚到结果不能应用，也不能自动写库。
4. 原图入口与锁定图片例外必须窄限定，不能越过父组锁。
5. 局部替换与描述生成允许用户主动更改主体身份，既有保真规则不能反过来阻止明确替换意图；只改指定对象/区域。
