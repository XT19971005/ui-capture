## 已修复事项

### Nginx 认证参数日志

旧示例未覆盖宿主默认日志。Nginx默认 `combined` 格式包含原始请求和Referer，认证回调的查询参数可能进入访问日志；上游错误也可能将原请求写入错误日志。[官方日志格式说明](https://nginx.org/en/docs/http/ngx_http_log_module.html)

以本机已有 `nginx:1.28-alpine`，在 `--network=none` 临时容器内启动假上游，发送固定的假 `code`、`state` 和Referer标记。旧示例检查失败，确认能够复现；没有使用真实凭据。

修复后 `shijie_safe` 日志只保留方法、无查询参数的路径、状态及基础运行数据；`/shijie` 跳转也使用同一格式。认证子路径丢弃可能包含原请求的Nginx错误详情，保留安全访问日志供定位失败。真实请求验证204、502和302三种状态均有记录，访问/错误日志均不含测试标记。

复跑命令：`python3 tools/check_nginx_logs.py`。无需安装Python依赖，不拉取镜像、不调用真实SSO；须预先具备测试镜像及Docker权限。线上使用不同Nginx版本时仍须执行目标机 `nginx -t` 和实际回调验收。上游代理日志不在该配置的控制范围内。
