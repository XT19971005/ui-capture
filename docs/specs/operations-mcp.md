# 拾界服务控制 MCP

拾界现有 `shijiectl` 只能在宿主机运行。本次增加与 qprole 同类的独立 MCP：查询状态、诊断、限定日志、任务查询、启动/停止/重启应用、备份、指定完整 Git SHA 发布、继续失败发布及后继修复发布。

沿用 qprole 的官方 MCP Python SDK、低权限 HTTP 进程和私有 Unix socket 执行器；只复用本项目发布所需部分，不复制视频/GPU 验收功能。控制程序安装为 root 管理的独立快照，业务停止或升级失败不停止控制服务。业务数据库不可用时拒绝身份校验，不降级放行。

默认个人 Token 模式；线上沿用 qprole 已配置的可信网关来源及逐请求 `X-User-Email`、`X-User-Name`，查询拾界当前超级管理员身份。只允许白名单内匿名静态发现，不提供匿名状态或日志。低权限进程没有 Docker 组和业务密钥权限；仅执行器可操作固定的拾界 Compose 项目。传输使用官方 SDK v1 锁定依赖，兼容现有网关。

发布只允许已登记仓库 origin/main 历史中的完整 SHA，拒绝倒退、分叉、未提交修改和任意命令/路径。构建成功后再备份和停写；保存 active/pending，失败保留原备份，不自动回滚数据库。修复版本必须是失败提交的后继且不得修改既有迁移。业务控制只接受 web、worker 或两者，不提供数据库停止和数据删除工具。

同机写操作互斥，任务及脱敏日志持久化；相同调用者/request_id 重试返回同一任务，不同参数冲突。断线不取消任务，执行器重启标记未完成任务中断。恢复前检查遗留维护容器。人工维护与 MCP 使用同一锁。

验收：真实临时 Git 仓库和 Docker 命令替身验证版本固定、备份保留、构建/迁移失败与恢复；官方 MCP 客户端验证发现、拒绝未认证/伪造来源/撤权/只读写入、重试和日志脱敏。Ubuntu 目标机验证独立服务、实际状态/诊断/重启、完整发布闭环，并比较同机其他服务启动时间。测试替身、线上验证和未验证事项分别记录。

不新增 CI/CD、通用 Shell、自动数据库回滚、GPU 控制或普通用户运维权限。MCP 发布权限等同可信生产代码执行权限；不承诺对恶意 main 代码提供沙箱。
