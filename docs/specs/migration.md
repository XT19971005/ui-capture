# 拾界独立服务迁移规格

## 当前问题
来源是桌面“拾界_便携分享版”。旧 Flask 服务绑定 127.0.0.1:19217，所有访问共用令牌、工程目录、Codex 进程与内存任务。Windows 便携 Python/Node、浏览器扩展及 explorer.exe 不能直接搬到 Ubuntu。旧工程文件有 CAS 版本检查与原子写入，但锁仅在进程内。

## 期望结果
项目位于 YHAgents/shijie，与 qprolevideopipelineweb 同级。沿用 qprole 的 Django/Gunicorn、PostgreSQL、公司 OIDC direct/Broker + PKCE、首次管理员和待授权账号、角色授权、TOML 配置、Ubuntu 24.04 Docker 和宿主反向代理。

## 保留契约
保留原图、拆分/续拆、图层编辑、精修、选区替换、生图、撤销、原生 PSD 和工程文件导入导出。只有明确保存才写工程；冲突返回 409，失败不得损坏原件；复用图片表去重协议，不自动降画质。保留原前端与算法，迁移其宿主边界。

## 有意改变
浏览器同源访问服务，使用 Django 会话与 CSRF；工程、任务、结果、AI 凭据按用户隔离。队列和中间结果持久化；页面关闭不取消任务。运行进程异常终止后保留中间结果并标为失败，允许用户手动续拆，禁止自动重试重复消耗额度。AI 账号由每位用户用设备码登录，账号文件不进入工程或发布包。禁用客户端修改服务端工程目录及打开宿主文件夹。

## 范围与非目标
本次为本地改造、Ubuntu 容器验证和远程部署准备；不连接远程服务器、不使用现有私人 AI 登录、不迁移历史数据。保留图片拆分及工程/PSD 能力。原生浏览器扩展、Figma 安装和在服务端交互打开第三方网页不属于拆图服务；网页工程仍可通过文件导入编辑，服务器抓取入口须明确提示不可用。不增加 Redis、Celery、发布 MCP 或通用插件框架。

## 结构与取舍
config 管设置和 URL；shijie/accounts 沿用 qprole 登录；shijie/pipeline 管每人工程、持久队列与执行；legacy 保留拆图内核和编辑器；deploy/tools 管容器与部署。浏览器 → Django → PostgreSQL/私有盘 → Worker → 独立任务进程 → Codex app-server。优于直接公开 Flask 的原因是原全局状态没有多用户边界；优于重写编辑器的是保留原生 PSD 与已有编辑语义。

ponytail: 首版使用一个 Worker 串行执行，同一数据卷的文件锁限制 Worker 数量，数据库行锁保证领取原子性。已知上限是同时处理一个任务；确有吞吐证据后再增加按用户公平调度和资源配额。工程沿用原文件格式，通过用户数据库行锁补齐跨进程 CAS，避免另造存储系统。

## 迁移与恢复
原始便携包和 qprole 仅作只读参考。新数据库、新数据卷、新 Cookie 与新 OAuth client_id；旧工程通过导出/导入迁移。升级先停止写入与 Worker、备份数据库及数据，再迁移；失败保持停机并恢复成套备份。无双写。旧本机入口在新工程中不运行。

## 验收证据
HTTP 测试覆盖登录重放/PKCE/待授权/撤权/CSRF；跨用户工程和任务不可见；两次旧版本保存不能覆盖；非法图像和路径拒绝；任务落盘、取消、失败恢复、结果读取通过测试。浏览器测试完成登录页、导入图像、手动保存重开和 PSD 导出。Ubuntu 24.04 Docker 从独立目录构建并启动 web/worker/db，数据库迁移和健康检查通过。

## 风险与未知项
真实公司 SSO 和个人 Codex 图像生成需要外部账号，交付须区分协议测试和真实推理验收。AI 图像生成依赖已登录账号及服务实际提供的能力，缺失应明确失败，不得伪造结果。原项目支持字体以 Windows 为主，Ubuntu 使用 Noto CJK 等字体；设计级文字一致性仍需代表性素材人工验收。所有测试和已知限制记录在 docs/verification.md。
