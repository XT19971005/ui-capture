拾界 · 图像重建模块研究记录
日期：2026-10-09
定位：研究与可行性验证；不是任意图片自动重建的完成版插件。

一、已经明确的需求
输入包括 UI 截图、流程图、海报、艺术字和一般图片。
目标是可继续编辑的设计结构，以及可运行的网页原型。
普通文字必须保留字符，不能仅导出像素层；艺术字与适合矢量化的图形需要保留路径。
输出以 Figma、PSD、HTML、SVG 和可再次打开的工程文件为主。
源文件、试验和输出统一保存在拾界插件项目内，不再独立维护研究版。
用户允许联网 AI，质量优先，付费调用前确认；随后明确希望直接由当前 Codex 中的助手负责 AI 分析。

二、推荐的实现路线
采用“Codex 协作模式”：用户在当前对话中指示处理图片，助手读取源图、识别文字与组件、重建设计结构，编辑器读取工程并呈现结果。
现阶段可以通过本地工程文件交换；正式集成可以用本地 MCP 暴露受限的读图、局部裁切、读取工程、应用修订、渲染与导出工具。
MCP 是连接工具的协议，不是替代模型的 AI 服务。由当前 Codex 会话分析，使用当前账号/组织既有的访问方式和额度；本次没有新增付费 API 调用，也没有连接或安装一个新的 MCP 服务。
如果未来要在独立插件里无人值守识别，再研究独立运行方案，不能把当前聊天页面当成无限调用的接口。
参考：https://learn.chatgpt.com/docs/extend/mcp?surface=cli
参考：https://learn.chatgpt.com/docs/auth

三、不能继续沿用“全部画到 Canvas 再拆图”的核心
旧版可以复用：Edge 入口、抓取页面、文件选择、预览、部分 Figma 导入逻辑、下载和 PSD 编码依赖。
需要新增：图像理解、文字识别校对、布局与组件树、矢量与原文并存、流程图关系、约束布局、原型交互、统一工程格式和每种格式的原生导出器。
需要替换：把所有文字和图形一律栅格化的 PSD 导出路径。PSD 格式支持文字和矢量，旧版只是没有实现。

四、统一工程数据是关键
建议用独立场景格式作为源数据，而不是把 Figma JSON 或 PSD 当唯一主文件。
每个节点保存：稳定 ID、类型、父子关系、坐标、尺寸、可见性、文字内容与字体、颜色、路径、蒙版、资源引用。
另外保存：源图区域、识别置信度、修改来源、需要复核项、布局约束、流程连线、交互动作、版本和撤销记录。
来源要区分：源图看见的内容、用户手动定义、AI 推断的结构。未确认的交互不能伪装成从截图还原出来。
照片与插画可以作为可替换的图像节点；不能为了声称“全矢量”把照片变成大量难以编辑的碎路径。
旧版网页 DOM 抓取仍可作为另一条输入；对已有 HTML 优先保留 DOM 提供的文字和结构，比从截图反推更可靠。

五、不同内容应采用不同处理方式
普通文字：识别内容与区域，按字体、字号、字重、行距、字距重建；识别后可以逐段校对。
艺术字：同时保存语义文字与矢量外观。轮廓可移动、缩放、改节点与颜色；修改字的内容后，需要重新生成轮廓。强光、金属、立体纹理通常要拆成多层效果，不能承诺简单 SVG 完全还原。
几何图标与装饰：优先重建规则图形与少量路径；需要时描摹位图，随后简化路径。
照片与复杂角色：保留位图、透明边缘与蒙版；如确需矢量风格，需要另行重绘并接受视觉变化。
流程图：识别方框、菱形、文字、连线、箭头方向与起止节点；交叉线和“连接/不连接”要复核。主文件保存 nodes 与 edges，不能只存箭头像素。
网页：生成真实 HTML/CSS/JS，建立约束与响应式规则；按钮、弹窗、选项切换等动作需明确。静态截图看不到服务器逻辑、账号体系或真实数据来源。
参考：https://github.com/visioncortex/vtracer
参考：https://reactflow.dev/examples/interaction/save-and-restore

六、输出格式分别验收
Figma：创建真实 TEXT、Frame、Vector 节点；正确加载字体。后续再加 Auto Layout、组件与原型关系。导出的是插件导入数据，不把 JSON 改名成 .fig 冒充 Figma 原生文件。需要 .fig 时由 Figma 客户端保存。
PSD：写入文字对象、字体信息、矢量蒙版/填充、图层组及像素预览。PSD 和 Figma 的排版引擎不同，必须分别处理换行、字体替换和效果。
SVG：普通文字保留 text，艺术字保存 path；图形不能用包裹 PNG 的 SVG 冒充路径。便携性需要在“保留可改字文本”和“文字转轮廓”之间明确选择。
HTML：输出真实 DOM 与受控交互；用浏览器测试尺寸、键盘操作和状态变化。
流程工程：JSON 保存连接关系；后续可以补 Mermaid / draw.io 等结构化格式，但不能只输出看起来相同的静态 PNG。
参考：https://developers.figma.com/docs/plugins/working-with-text/
参考：https://developers.figma.com/docs/plugins/api/figma/
参考：https://github.com/Agamnentzar/ag-psd
PSD 库官方明确说明文字实现不完整且不会自动重绘预览，复杂情况需要 Photoshop 实际打开并重新保存验证。当前不能仅凭库回读就声称 Photoshop 完全兼容。

七、本次实际做过的验证
1. VTracer 0.6.15 在独立依赖目录运行，把特制“拾界”PNG 标题描摹为纯路径 SVG。
2. 建立受控设计工程，包含中文文字、艺术字路径、三个流程节点和两条带起止 ID 的连接。
3. 生成 PSD 并回读：11 个文字层、11 个矢量层、18 个路径轮廓；检查了 TySh 和 vmsk 数据块。
4. 在独立 Edge 中打开“编辑能力验证.html”，把文字改为“中文可以直接修改”，拖动节点，运行三步流程。
5. 下载修改后的 PSD/Figma 数据/SVG/工程 JSON，验证新文字进入 PSD 原生文字字段，矢量路径仍存在，流程关系仍存在。
6. SVG 验证没有 image 元素或 data:image 栅格嵌入；浏览器无页面脚本错误。
这些输入是受控样例，不是一次任意图片自动识别的效果展示。

九、建议开发顺序和验收门槛
阶段一：打通“当前对话读图 → 工程 → 编辑 → 原生导出”。选择一个真实 UI 截图和一个流程图作为首批对象。
阶段二：补文字校对、字体替换、路径简化、图像蒙版、局部重建、撤销/重做和差异预览。
阶段三：补约束布局、多状态页面、组件、交互与多格式输出。
阶段四：用真实样本在 Figma 与 Photoshop 中逐项验收，再做正式插件安装包。

验收须同时记录两类指标：
视觉：位置、尺寸、边缘、颜色、字体、换行；以原图与重建渲染叠加和差异图辅助检查。
结构：每段文字可重新输入；路径可调节点；节点可独立移动；连线端点正确；导出后保存重开不丢失。
不把某个图库的 OCR 分数当作本插件的还原率；不提前承诺任意图片 100% 还原。

十、可选辅助能力
PaddleOCR 官方提供浏览器侧识别 SDK，返回文字、区域和分数，可作为本地坐标辅助；这并不自动解决 UI 分组、字体、交互或流程关系。本版还未集成。
参考：https://github.com/PaddlePaddle/PaddleOCR/blob/main/paddleocr-js/packages/core/README.md
Photoshop 部分较新的 UXP 文字 API 对版本有要求，兼容用户当前客户端必须实测，不能直接照最新文档假设可用。
参考：https://developer.adobe.com/photoshop/uxp/ps_reference/classes/layer/
