# 局部替换与手动保存 Implementation Plan

> 使用 executing-plans 执行；按独立文件范围并行处理存储和生成后端，主任务实现入口并在网页整体验证。

日期：2026-10-16。用户已明确整张未拆图片框选替换、拆分后单独素材替换；描述和参考图均可输入。不主动下载 PSD。

## 目标与设计

现有 JavaScript 工作台 + 本机 Python 服务继续使用，无新账号或生成服务。

- 统一“替换图片”窗口：整张未拆图片也可直接进入；拆分工程只处理一个已选图片层。支持整层/框选局部，参考图可上传并框选取用。文字描述或参考图至少一项。
- 选区在原始图层图片像素坐标定义，不以画布缩放像素作为生成坐标。图层位置、大小、旋转、蒙版、父组及未选层不变。局部结果仅合成回选择区域，区域外像素精确保持。
- 生成只产出候选预览，不改变工程；用户“应用替换”才替换，隐藏旧版、一步撤销。取消/失败/切工程使候选失效。模型内容、边界自然度仍需看图，不将数据测试视为美术通过。
- “保存工程”才写工程库；导入、移动、替换、精修、自动阶段/关闭 flush 不自动写。已有库记录保留，未保存改动离开页面需明确提示。标签可恢复最后手动保存版本，不冒称最新编辑已保存。
- 图片工程的“回到初始”固定为首次完整拆分成功快照，并随手动保存/导入导出保留。打开、精修、手动保存不得重设。重新拆分成功产生新基准；未完成不设成完整拆分基准。旧工程缺少快照需说明，不能以当前修改状态冒充。

## 接口约定

新增 jobs mode `replace-image`，请求附 `replacement: {targetId, region, prompt, reference}`。

- region 为 null（整层）或原图片像素整数框 `{x,y,width,height}`；reference 为 null 或 `{src,region}`，坐标同其自然图片尺寸。
- 后端 `image_replace.validate_replacement(scene, replacement)` 在模型前验证；`process` 沿用现有任务生命周期，增加 `replacement` 关键字参数。只返回候选 scene，不写工程库，不导出 PSD。
- 前端 `ShijieSmartSplit.replaceImage(doc, replacement, onProgress)` 复用任务连接/取消/清理。
- 新窗口模块 `image-replace.js` 通过 `studio.adapter.get()/restore()/finish()` 和 `studio.ids` 访问当前工程；生成期间任务锁生效，应用前核对 owner 与完整输入快照。源图上传锁只允许未拆单原图的显式替换；普通锁定层/父组必须先解锁。
- 基准元数据独立可版本化，避免递归包含自身；数据压缩、尺寸和恢复校验沿用工程编码器。初始快照不进入生成请求以免扩大模型输入。

- [x] 前端：入口、选区缩放映射、参考裁选、文字输入、候选预览/应用/撤销/取消测试；不触发全图扫描或自动保存/导出。
- [x] 网页：实际未拆图片和已拆素材两入口；实际框选、上传、生成预览、应用/撤销、手动保存重开及初始恢复。存储基准使用明确合成夹具，真实生成使用用户换头截图，边界详见当天变更记录。
- [ ] 更新当天变更记录及技能存储新约定；同步入口、刷新分享包、验包，源码 Git 提交并核对远程。

## 审查重点

1. 矩形选区在图层局部像素而非舞台坐标；不同分辨率参考图不得串坐标。
2. 保存基准不能递归膨胀；快照及候选不能通过异步回调污染新工程。
3. 点击取消后晚到结果不能应用，也不能自动写库。
4. 原图入口与锁定图片例外必须窄限定，不能越过父组锁。
5. 局部替换与描述生成允许用户主动更改主体身份，既有保真规则不能反过来阻止明确替换意图；只改指定对象/区域。
