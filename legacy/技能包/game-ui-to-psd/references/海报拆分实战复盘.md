# 欢乐斗地主海报拆分复盘（2026-10-12）

本记录来自实际失败、返修和用户反馈。适用的是判断方法，不是这张海报的人物轮廓、坐标或固定参数。

## 1. 完整底稿与显示遮罩是两件事

用户明确允许：先做完整素材，再加可关闭的遮罩；图层特效也可以保留。此前“一律不能加遮罩”的表述过严，已纠正。

- 完整性约束针对源底稿和图层内容。不得删除被遮挡部分、改写底稿 alpha，或把残片登记为完整素材。
- 显示范围可以用独立图层蒙版、父组蒙版或适当的剪贴关系控制。关闭遮罩后，完整底稿必须仍存在；移动上方遮挡物时能恢复和调整显示。
- 遮罩不得掩盖坏提取、缺笔画、身份变化或背景污染。检查遮罩开启的最终画面，也检查关闭后的完整素材。
- 此项目的上方祥云初稿左端人为截成斜直边，和原图幕布遮挡不一致。修为完整圆端底稿加父组显示蒙版，分别保留完整形状和幕布遮挡曲线。
- 当前导出器实现父组 `displayMask: {d, reason, disabled?}`。`d` 是画布坐标路径，白色区域显示，黑色区域隐藏；导出原生组蒙版。直接素材蒙版或剪贴尚未完成验证时应报工具限制，不把限制写成用户禁止。

## 2. 人物不能只看整体“像不像”

全海报提取多次改变真人头发、脸和衣纹，即使整体位置、特征点配准和透明度检查通过，也不代表可见细节正确。

- 先用紧邻主体的原图参照提取，逐处核对脸、发丝、肩、双手、蝴蝶结、服装和裙摆；卡通核对表情、手指、帽带、手机、杆和脚。
- 明显身份、肢体或衣纹漂移返修，不能靠写“生成差异”放行。原图脸和可见衣纹能保留时优先保持。
- 原图自身轮廓提取与“原图 RGB 套模型 alpha”不同。前者来源一致，后者因局部错位会混入背景、文字和硬边，禁止。
- 被文字遮住的白布与红裙必须分材质补绘，不能用同一颜色扩散产生红块或矩形接缝。不可见衣纹属于推断，如实登记。
- 确认最终素材后固定哈希和同源 RGBA；只修改底稿时应明确重新登记和复核，不能自动更新哈希掩盖失败。

## 3. 微弱渐变也不能漏掉

信息条实际为左白右金，大标题有纵向奶金变化，姓名板有细微色差，挂灯包含金属光照和中心发光。单点取色会把这些效果变成纯色。

- 登记每个渐变对象，分方向和位置采样；不要把 JPEG 噪声逐像素拟合成色标。
- 矢量用原生渐变填充，普通文字保留原生文字并使用渐变叠加；位图保留自身光照。
- `ag-psd` 的比例参数为归一值，`scale: 1` 是 100%，`scale: 100` 会写成 10000%。检查实际 PSD 色标、方向、缩放和偏移，再看独立合成。
- PSD 缓存正确不代表原生渐变正确。本次新增横向、纵向、径向及错误缩放拒绝测试。

## 4. 图层样式应保留且能关闭

外发光、描边、阴影、渐变叠加等按原图需要使用，不因“完整素材”约束禁止样式，也不为了增加特效而任意添加。

- 可编辑样式与显示缓存同步。开关样式检查视觉变化；关闭后主体 RGB 和 alpha 不应被烘焙光晕或阴影污染。
- 参数遵循导出器格式。例如外发光尺寸使用 `{units: 'Pixels', value: 18}`，启用状态与透明度也要回读。
- 当前合成器未支持的样式必须扩展并验证或说明限制，不能仅写描述后宣称显示正确。

## 5. 原生矢量要检查实际孔洞和轮廓

梅花初稿三个重叠圆在回读中形成不应有的小孔。修为统一连续外轮廓后再检查。正常平滑几何减少冗余点；原图毛绒、笔刷边缘保持风格。模糊品牌先确认版本和准确文字，再找清晰同款或重建；近似旧版标识注明来源边界。

## 6. 自检分三层，不能互相代替

1. 来源检查：完整底稿哈希、同源 RGBA、变换、文案和来源登记。
2. 原生检查：实际 PSD 文字、路径、渐变、蒙版、样式及独立合成；验证坏版本确实会被拒绝。
3. 实际看图：原图与最终合成、每个独立层、人物局部深浅底、遮罩和特效开关。

透明 PNG 在 alpha=0 像素中的 RGB 可能造成查看器误导；在棋盘格及深浅底合成后判断残留，不凭透明图片的 RGB 外观裁坏轮廓。工具通过只能证明已覆盖的检查，不代表 Photoshop 客户端编辑测试已完成。

## 7. 复核必须绑定当前版本

更改素材、遮罩、路径或特效后，旧画面记录过期。重导出、回读受影响图层和整体，再写实际观察；不能运行旧的“全部通过”记录脚本冒充新一轮看图。旧错误版本归档，项目脚本与最终来源说明同步。

## 8. 工具选择与交付习惯

本会话可用内置 `image_gen`，不需要先向用户索要 API key。默认先检查当前能力；仅文件输出遵守本用户要求，图片保存在项目，不在聊天发布。API/CLI 需用户选择。维护只改本用户技能包，同步 Codex 入口并刷新分享包；不要修改系统管理的内置技能和依赖来绕过检查。

## 9. 历史精细要求（后续已调整）

这是用户较早提出的精细要求；后续已由第12节的速度优先、约80%实用交付标准覆盖，不再作为无限返修的门槛。原始要求为：尽量完全一样，保底一样，能更好一定更好。首先对齐原图可见内容、轮廓、比例、位置、颜色、人物细节及光照。提升清晰度、边缘、补全和可编辑性，不能任意改设计。原图无法恢复的隐藏内容标明推断；仍存在可见差异时继续返修，不把工具 PASS 或差异说明当成精度达标。

## 10. 主人物辨识度优先

用户再次强调主人物不能差别太大，否则就不像。真人和卡通都按身份、神态核对：脸型、眼形和视线、鼻嘴、发型、表情、姿势及标志性服装保持一致；清晰度提升和美化不能改变这些特征。脸部或神态明显漂移是必须返修的问题，不是可通过说明豁免的材料差异。仅核对部分脸部 RGB 不变不能证明整个人物符合要求，仍需发丝、脸、双手、服装和整体比例检查。

补充复核发现：挂灯原生外发光参数存在，但独立回读工具对外发光的显示支持有局限；必须同时看合成预览、关闭特效后的主体和原图。不能把原生样式存在或全图误差很小当作局部光效一致。本次继续调整光晕、金边细描边和祥云轮廓细边。未做 Photoshop 客户端效果验证时如实说明。

原生描边在当前 ag-psd 中以 effects.stroke 数组编码，即使只有一条描边也不能传单个对象；实际导出和回读验证，不能只检查项目 JSON。

祥云新增细描边在独立回读时出现异常横条，实际看图发现后已撤回这项样式。不能因结构检查通过而交付异常图层。保留完整形状及组显示蒙版；金框描边另行实际查看。原生效果与独立渲染器兼容性应逐对象判断。

整体回读又发现挂灯细描边产生小外延线，最终也撤回金框描边，保留已验证的渐变和外发光。局部图册看似正常仍需检查整张图，避免漏掉框外细线。

## 14. 两目录收尾（2026-10-12，取代早期三目录习惯）

项目根仅1_过程、2_输出。过程仅素材、结构、检查；原图与最终PSD仅在输出。图册放检查内，不另建工作区。PSD不保存整张原图或完整组合的冗余隐藏参照组，真正参与重建的完整素材仍保存。迁移先核验原图哈希，再同步素材引用和重建脚本；移除隐藏组后验证合成像素完全一致，并回读文字、矢量、蒙版和特效。目录整理通过不等于修复已有画面问题，原有待复核状态不能自动改成PASS。
