替换当前项目的实际尺寸，不沿用例子。PowerShell 入口不默认操作上一张海报。登记后将 spec 放入项目清单，生成、识别与实际看图由 agent 完成；`run` 不会自行调用图像模型。

脚本也可直接调用：

- `node scripts/pipeline.cjs init|status|build|verify|run --project DIR`。`status` 查看缺项与可复用阶段；`build` 只导出；`verify` 复查素材来源及 PSD；`run` 导出、回读、生成检查图；`--force` 忽略导出缓存。
- `node scripts/register_asset.cjs --project DIR --file PNG --name NAME --role character|background|artwork`。可设置整体位置尺寸；不会自动改层级。不同素材的同名覆盖要明确 `--replace`。
- `python scripts/trace_shapes.py --project DIR --regions JSON`。原图颜色轮廓分析，输出原生矢量描述；不减去角色 alpha。
- `python scripts/smooth_paths.py --project DIR --regions JSON` 或 PowerShell `smooth -Project DIR --regions JSON`。把完整颜色轮廓拟合为三次贝塞尔曲线，控制轮廓平滑和拟合误差；默认输出 `02_结构/平滑矢量.json`。区域可设置 `smoothPixels / tolerance / minimumArea`，必须看图确认没有改变字形、填掉孔洞或丢掉小字。
- `node scripts/import_psd.cjs --psd FILE --project DIR`。保留已有 PSD 的原生文字与形状；可用 `--character-layer / --character-file` 和对应 background 参数替换完整素材。先将原图放在 2_输出，项目清单已存在时不覆盖。
- `node scripts/render_checks.cjs DIR`。只保存检查图。
- `node scripts/review.cjs init|check --project DIR`。创建待实际检查的清单或检查已填写记录；不自动判定画面合格。
- `node scripts/doctor.cjs`。检查运行环境，不调用付费 API。
- `node scripts/selftest.cjs --out 隔离测试目录`。实际导出和回读小型测试，并确认坏艺术字、人物 RGB 污染、缺笔画年份及未完成看图记录被拒绝。

使用 PowerShell `run` 会自动创建画面复核清单；直接调用 Node `run` 后还须执行 `review init`。

### 本机网页手动工程目录（2.37）

本机网页点击“保存工程”默认写到工作区 `工程文件`，运行时从应用根目录的父目录解析 `ROOT.parent / '工程文件'`。此目录是用户主动保存的工程库，不属于独立素材、检查图或运行临时目录，不按任务结束自动清理，也不代替 `交付包/项目名/1_过程、2_输出` 的正式PSD交付结构。便携移动解析相对位置，不将开发者机器的绝对路径写入分享包。

保存采用单工程原子替换和版本校验，列表读取元数据，打开时才解码正文；只在磁盘写入成功确认后显示已保存。旧浏览器工程和凭据保留；导入、打开旧记录、编辑和生成均不自动转存，之后明确手动保存才建立磁盘版。扩展兼容原存储，不因本机网页切换默认目录而删除旧记录。工程文件迁移、打包及备份须区分用户保存数据与测试夹具，不能把本机工程库或账号凭据收进分享包。
