# ImageGen 抠图、补全和存档

这份规范将 ImageGen 纳入拆图流程。ImageGen 技能文档及官方 CLI 原样副本统一位于根目录 `技能包/imagegen`，使用前读取相邻 `../../imagegen/SKILL.md`。系统原版仍由 Codex 管理；副本不自动跟随系统更新。内置图像工具属于当前会话能力，不能靠复制文件夹获得；调用参数以当前工具文档为准。

## 选择处理方式

- 先确认输入角色：操作示意截图用于理解交互，不能直接导入当原图、待替换对象或生成参考；用户明确指定为实际素材后才使用。画面里出现参考图或示例人物不等于用户要求替换该人物。
- 用户主动“圈选编辑”：在主画布手绘自由选区，Shift追加区域取并集，描述与参考图放右侧，保留“选区参考生图/局部替换”两种模式，默认reference参考模式。参考模式仅把选区裁图与描述交给独立生成面板，不修改原图、不改变当前工程已保存状态、不自动发起生成；局部替换只在用户明确选中该模式时回贴指定区域，先预览再明确应用，区域外原RGBA和完整底稿保持。
- 用户主动“生成图片”：以独立入口接收文字或参考图生成新图，无需先提供拆分原图或选中层。候选是独立素材，先预览，再由用户手动下载PNG或添加新层；仅添加新层改变工程，且不自动保存，不能把参考生成结果默认覆盖来源原图。输入变化、取消、失败或切工程使过期候选失效，不自动付费重试。主动改变新素材内容按用户意图执行，不用忠实提取规则拒绝明确生成需求。
- 完整透明资产已存在：读取并检查后使用整张 RGBA；需要控制显示范围时增加独立可关闭蒙版，不删除底稿内容，不把可见残片或原图矩形块写入完整底稿。
- 纯色数字或规则控件：在原生矢量中补全；同图重复的完整数字可复用，避免改变字形。
- 缺少完整人物、艺术字、纹理图标或干净背景：用图像编辑提取及补全。保持原图主体、身份、姿势、服装、比例和布局，只改变需要处理的部分；有明显漂移就返修。
- 人物颜色与 alpha 必须来自同一张最终底稿。模型输出不与原图 RGB 跨来源拼接。
- 浅色、大面积或底部区域若有独立边界与遮挡关系，仍是独立前景；明确纯色优先矢量。背景去件清单覆盖该前景的来源ID、几何和层序，不能把原生矢量前景烘焙进背景；无证据不新造平面。不硬编码特定画面，也不据新规则自动重画旧工程。

## 内置工具

默认使用当前会话提供的 `image_gen`，无需 API key。编辑本地图片先用图像读取工具实际检查。按工具文档传入全部目标参考图；有完整本地路径时使用 `referenced_image_paths`，只有会话图时使用最少必要的 `num_last_images_to_include`，两者不混用。

人物、艺术字、纹理图标设置真实透明背景；背景补绘保持不透明。不能把黑底、白底或棋盘格画进图里冒充透明。

默认生成文件在 Codex 的 `generated_images`；把选定结果复制进本项目 `01_素材` 后再登记，不让 PSD 只引用临时生成目录。源底稿与提示词、输入角色、采用情况记录在 `02_结构`。新素材未检查时不覆盖已确认资产。

本用户要求只存文件夹。有些内置工具会自动展示生成结果；若当前工具会展示，不调用它来违反这个要求。优先复用已有完整素材或采用已经可用且获授权的仅文件输出流程。CLI/API 必须用户明确选择，不能为了文件路径或省略展示而静默切换。需要补绘但没有兼容的可调用方式时明确指出这个限制，保留项目与已完成工作，不用裁坏素材顶替补全。

## 复核不完整不得重生成（2.34）

复核类别缺失、重复或观察为空时，拒绝该复核结论，保留已有素材和工程并说明证据未完成；不能把协议/读图不足折算成画面FAIL后自动付费重画。先补齐当前原图、独立素材及PSD回读证据；仅完整实际证据确认的错误可进入已授权的一次有界修正。继续拆分只生成尚未完成项，已完成素材及手改不因缺少复核证据被替换。

## 拆图提示词

按实际对象改写，保留以下约束；不要把整张海报作为风格参考重新设计。

人物提取：

```text
Use case: background-extraction
Asset type: 游戏 UI 的完整透明人物素材
Primary request: 从编辑目标中提取 [完整人物/完整角色组合]，补全被 UI 遮住的部分。
Input images: Image 1 是编辑目标，保持其人物身份、面部、姿势、服装、持物和原始布局。
Constraints: 人物连同帽子、帽带、手、衣袍和持物保持完整；真实透明背景；去除标题、日期、边框、按钮和标识；没有橙色背景残片、破洞或拼接接缝；不要重设计人物。
```

艺术字提取：

```text
Use case: background-extraction
Asset type: 完整透明艺术字
Primary request: 只提取“[原文逐字填写]”，补全被人物或其他元素挡住的笔画。
Constraints: 原始行数、字形、排列、笔画、颜色和纹理；每个字完整；真实透明背景；去除人物、旗子、标识和背景；不换字体，不把当前可见残片当成完整字形。
```

干净背景：

```text
Use case: precise-object-edit
Asset type: 可单独使用的完整背景
Primary request: 去除人物、UI、标题、日期、按钮、标识和边框，补绘它们遮住的背景。
Constraints: 保持原始镜头、透视、光照、建筑或纹理结构、画布比例；完整不透明背景；没有人物、袖口、文字残片、矩形补丁或棋盘格；不重新设计场景。
```

## CLI/API 连接

只有用户明确选择或确认 CLI/API 模式时使用 `scripts/imagegen_cli.ps1`，它调用相邻 ImageGen 包内原样收录的官方 `image_gen.py`，没有另写 SDK。读取该技能及其 `references/cli.md` 后传入参数，显式设置项目输出路径。不能修改官方脚本；不在聊天索取或打印完整 API key。

模型选择和透明参数随实际官方 CLI 文档核对，不默默降级。只把 API key 是否配置当作状态，不输出值。`doctor` 和 `selftest` 都不会调用图像生成或产生 API 费用。
